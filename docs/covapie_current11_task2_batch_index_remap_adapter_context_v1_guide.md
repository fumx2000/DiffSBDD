# CovaPIE Current11 Task2 remap adapter context V1

This product adds exactly two public, keyword-only APIs: `build_covapie_current11_task2_batch_index_remap_adapter_context_v1` builds an opaque authority context, and `remap_covapie_current11_task2_batch_index_with_context_v1` returns only the current adapter's built-in Output17 dictionary.

The context implementation is private, slotted, frozen, deeply immutable, and tamper-evident. Its construction seal is SHA256 over the domain `COVAPIE_CURRENT11_TASK2_BATCH_INDEX_REMAP_ADAPTER_CONTEXT_V1\0` followed by canonical JSON for logical fields 1 through 19. The full logical contract has exactly 20 ordered fields, ending with `construction_seal`. The context is bound to its construction authority snapshot; freshness is `explicit_rebuild_by_owner`, with no automatic refresh or per-batch filesystem check.

Production context construction is clean-only. In `precommit-untracked`, the public builder fails closed before reconciliation, successor, or B2 can run. Candidate tests and the checker use a private fixture-only injection path. Their narrowly scoped lifecycle compatibility patches obtain one real reconciliation Exact6 and one real successor Exact6, including the successor's one internal B2 call, and always restore the published functions in `finally`. Production code does not monkeypatch lifecycle observation and calls B2 directly zero times.

For a clean tracked successor, one context build performs one reconciliation public acquisition and one successor public acquisition. It independently validates the reconciliation digest/model/runtime target and the successor stable5/report, validates formal authority before and after acquisition, and requires both formal snapshots to match. The successor-aware parser consumes stable5 without an old historical report. It reuses the current adapter's frozen JSON, CSV, identity, and role-authority helpers while checking schemas, field order, status vocabulary, join/index spaces, placeholder semantics, digest lineage, Exact11 source order, Exact22 roles, selected row/local mappings, and selected atom Exact8 identities.

Each fast call validates the exact private context type, versions, runtime target, and seal; materializes fresh built-in source/authority structures; deep-copies and validates the caller input; then invokes the frozen current adapter `_validate_source_contract`, `_remap_engine`, `_failure_output`, and `_validate_output` helpers. It neither copies the full remap algorithm nor defines another status precedence. Success and deterministic failure must whole-Output17 match the current public adapter, including provenance, readiness, offsets, validity, failure placement, nulls, and bool/int types. Historical private failure output is not the runtime golden and failure normalization is forbidden.

The per-batch path performs zero reconciliation, successor, B2, historical-gate, adapter-public, formal, filesystem, Git, subprocess, report, artifact-write, context-rebuild, or cache operations. There is no global registry, LRU cache, singleton, cross-process cache, pickle contract, or new fast report. The existing slow adapter remains byte-for-byte unchanged.

This increment does not modify canonical masks, DataLoader, model, head, forward, loss, checkpoint shapes, or training behavior. Canonical V1 remains exactly `warhead_only/A`, `linker_plus_warhead/B`, `scaffold_plus_warhead/B2`, `scaffold_only/B3`, and `scaffold_plus_linker_plus_warhead/C`. Step12D remains a smoke legality check, not a final training-feature contract. The historical unknown-atom feature policy and `feature_semantics_known=False` state still require a feature-semantics re-audit before training; training readiness remains false.
